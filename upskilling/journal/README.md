# Journal

Your weekly entries go here, one file per ISO week: `YYYY-Www.md`, for
example `2026-W40.md`. Copy [the template](../templates/weekly-entry.md);
[the worked example](../examples/weekly-entry-2026-w39.md) shows the level of
detail to aim for.

## These entries are public by design

This folder is committed. That is deliberate. The 90-day plan's exit
criteria, the matrix self-assessments and the Arc 3 estimation calibration
all link to entries here. A mentor, a reviewer or a future employer can only
check what they can open. An entry on your laptop is a diary. An entry in the
repo is evidence.

So write every entry as if a colleague will read it, because one might.

- **Keep out:** anything about named people other than public authors,
  health, money, the job you are applying for, and anything you'd be unhappy
  to see quoted. Keep personal notes outside the repo, in a file of your own.
- **Keep in:** what you did, what you decided and why, what you got wrong,
  numbers with their commands, and links.

Writing "I got this wrong" in public is itself a senior behaviour. The
entries that show a mistake and what you changed afterwards are the most
useful ones in the folder.

## Rules

- One entry per week, written in the same slot each week, even when the
  week went badly. A short entry beats a missing one.
- Never rewrite an old entry. Add the "Four weeks on:" line at its bottom
  when you re-read it; that line is the only edit allowed.
- Numbers go in the "Estimate vs actual" table with the columns in the
  template's order and hours as decimals, so Arc 3's ratio is one pass over
  the files.
- No code files here. See the [folder rules](../README.md#folder-rules).
